# Serein 情感陪伴 Agent：调研与实施计划

调研与修订日期：2026-10-21。版本：v2，依据[修改建议稿](emotional-agent-revision-proposal.md)修订。状态：方案草案，尚未开始开发或部署。

调研方法：查阅项目主仓库、维护方文档和飞书开放平台文档。本报告属于文档调研，未安装这些框架、登录微信/飞书或实测稳定性。以下将已核实的能力与产品建议分开说明；平台资格、接口限制和插件版本仍需在实际账号上验证。

本次修订收紧首版范围，补充选型证据、模型对比、数据生命周期与阶段验收。所有人数、工期、保留期限和指标均为待验证的计划参数，不表示用户已确定选择，也不表示已经实测。

## 1. 目标、假设和验证条件

Serein 的长期方向是中文日常情绪陪伴。首轮验证暂以**成年职场新人在工作受挫后的文字倾诉**为场景，通过小范围邀请测试，验证用户是否愿意使用、回应是否贴合，以及少量可控记忆是否改善体验。人群和场景均是待验证假设。

飞书是待验证的首个渠道候选。先完成代表实际招募范围的用户加入、授权和私聊实验；渠道不适合时，使用简易文本测试入口验证相同核心，重新确定唯一试用入口。第一版暂不包含主动跟进、跨会话事件记忆、自动摘要或第二渠道。

开发前形成一页决策记录，注明决策人、日期、依据和未解决事项：

| 决策 | 暂定假设 | 验证方式 | 对方案的影响 |
| --- | --- | --- | --- |
| 自用或产品试用 | 受邀成年人试用 | 明确项目目标、维护人及预算 | 仅自用时不开展多用户产品建设 |
| 首发场景 | 成年职场新人的工作受挫倾诉 | 访谈约 5–8 人，讨论近期经历、替代方案和使用障碍 | 缺少共同需求时重选场景 |
| 首发入口 | 飞书私聊 | 目标组织外、代表实际招募范围的用户完成加入、授权和私聊 | 进入受阻或排斥入口时更换渠道 |
| 核心增益 | 回应更贴合，且记忆可控 | 同模型下对比普通人设、陪伴策略及最小记忆 | 无稳定增益时先改对话方式 |
| 云模型与预算 | 尚未确定 | 记录处理路径、供应商保留规则及总预算 | 未明确前只用合成数据做离线实验 |

访谈不要求提交完整私人聊天记录。愿意讨论困扰，不等于愿意持续使用产品。内容处理路径与用户说明确定后，才能将真实倾诉提交至对应模型服务。

技术暂定为独立、轻量的陪伴核心、单渠道、可替换模型和可确认偏好记忆；接入采用官方 SDK 还是框架适配层，由第 2 节的限时实验决定。若目标仅为自用，可另选 OpenClaw 配置原型；配置所需时间也需验证。

第一阶段的投入重点是对话增益、用户控制和工程可靠性。试用暂定 5–10 名成年人，持续观察 7–14 天；语音、数字人、多角色、复杂工具和微调后续评估。

### 两个值得借鉴的机制

**人格与业务逻辑分开。** Hermes 使用 `SOUL.md` 定义长期人格，另有会话级人格设置。可以借鉴这种分层：温和、直接程度等风格保持稳定，当前该倾听、追问还是提供建议由对话策略决定。[Hermes 人格文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/personality)

**短上下文与长期记忆分开。** Hermes 的持久记忆包括 `MEMORY.md`、`USER.md` 和历史会话检索；文档特别提醒，回复“记住了”不代表实际写入成功。Serein 必须把记忆写入作为可检查的操作，并明确区分会话记录隔离与长期用户记忆隔离。[Hermes 持久记忆文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)

### 2.2 一个有时间上限的集成实验

首轮仅选一个框架，建议初始候选为 OpenClaw，实验预算半天至一天；不实际安装所有候选。用最小样例确认：

1. 入站能否在模型调用前交给自有服务，并保留稳定身份和消息 ID。
2. 是否能关闭内置记忆及工具，避免维护两份用户状态。
3. 自有服务能否控制发送、失败结果及账号凭证，原文能否按保存模式绕开持久化。
4. 选定版本的许可证、模型服务条款及渠道条件是否适合计划用途。

将“官方 SDK 直连”和“该框架作为适配层”的集成工作量、升级成本及已知限制写入决策记录。无法关闭原文持久化或无法在模型调用前授权时，不能作为首版适配层。超预算仍无结论时标为未验证，停止扩大调研；直连接入也需按同一准入标准验收。

### 2.3 中文多轮模型对比

先筛模型，再固定模型比较策略。用约 20 个合成多轮场景，对 2–3 个实际可调用候选模型给出相同历史、输入及输出要求，记录供应商、具体版本、采样参数、提示词版本、完整回复耗时、输入/输出 token、缓存及实际费用。未调用的模型标为待测，不写排名。

初筛检查中文语气、连续拒绝建议、少说话要求、话题转换、事实一致性及服务故障。开发集用于调整提示词；独立验收集及规则在正式验收前冻结，失败不得直接改成迁就当前实现的答案。新增缺陷可加入开发回归集；若泄露验收样本影响评测，应重建独立集并记录原因。

## 3. 渠道准入与切换条件

### 3.1 飞书候选必须通过真实加入实验

飞书官方文档说明，长连接接收事件不需要公网回调地址，但服务需要访问公网，且长连接适用于企业自建应用。事件需及时确认，否则会重试。[飞书开放平台：使用长连接接收事件](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

SDK 接入可行性与用户接受度分别验证。进入试用前必须完成：

- 开发者与一名代表实际招募范围的受邀用户，均完成加入、授权和多轮私聊；包括目标组织外的进入路径。
- 记录实际应用类型、组织关系、可用范围、必要发布配置及权限，不能假设所有账号条件相同。
- 未授权用户不能进入模型调用与内容存储；撤销邀请后不能继续使用。原文不进入鉴权失败日志。
- 事件快速确认与后台生成分开，验证断线重连、重复事件、发送失败及投递结果未知。
- 目标用户理解消息将经过渠道和模型供应商，愿意用该入口倾诉；机器人私聊不能被描述成端到端私密。

加入或使用意愿验证失败时，先用简易文本入口验证陪伴核心，再重选唯一试用入口并重估工期；不在同一计划中同时建设多个替代渠道。

### 3.2 微信正式接入后移

微信属于第二阶段。若用户明确要求微信首发，则先验证微信准入，再重排全案，不临时塞入第 3 周。

本轮复核的 OpenClaw 维护方文档说明：微信插件 **2.4.8** 不接入标准配对流程；旧白名单及扫码身份回退与 SQLite 配对存储存在授权、撤销不一致，特定空配置回退条件下可能允许到达插件的发送者。这是该版本的文档声明，采用其他版本必须重新核验。[OpenClaw 微信访问控制](https://docs.openclaw.ai/channels/wechat#access-control)

采用存在此限制的插件时，不依赖标准配对命令管理访问。进入自有核心前执行独立授权检查，至少测试未授权、撤销、空配置和重启四种情形；不能满足时不开放多人试用。

Hermes 文档说明，二维码连接的是 **iLink Bot 身份**，不能据此推定可以接管普通个人号的好友消息、历史记录及普通微信群。文档也记录了 context token 失效、用户需先发送消息等发送限制。以上只能作为研究依据，不能代替实际账号验证。[Hermes Weixin 文档](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/weixin)

第二阶段逐项验证账号授权、Bot 的实际入口、其他受邀用户能否联系、独立白名单、凭证恢复、重复事件以及长时间无入站后的发送结果，再决定产品承诺。

### 3.3 公众号、企业微信另行评估

这些属于不同产品入口。面向外部用户发行时，另查申请主体、进入路径、回复窗口、主动发送限制及审核要求；本报告不把它们视为已验证的发行方案。

## 4. 对话体验和最小记忆

### 4.1 接住当下，允许不追问

根据近期上下文理解用户想倾诉、被理解、理清事情、寻找办法或安静陪着。类别仅作可修正指导，允许未知状态，不要求每轮分类后按模板执行，不固化为人格或诊断标签。

| 当前需求 | 建议行为 |
| --- | --- |
| 倾诉 | 短回应、回应具体处境、留出表达空间 |
| 被理解 | 温和表达对感受的理解，允许纠正 |
| 理清事情 | 用户愿意时一次问一个关键问题，区分事实与猜测 |
| 找办法 | 有意愿信号后给一两个小步骤 |
| 安静陪着 | 减少追问，允许自然停顿与结束 |

行为示例，不是固定话术：

> 用户：“今天被领导骂了，我觉得自己特别没用。”
>
> 助手：“被领导那样说，今天应该挺难受的。你想说说刚才发生了什么，我听着。”
>
> 用户：“别分析，我只想吐槽。”
>
> 助手：“好，不分析。你说，我听着。”

评测覆盖连续几轮拒绝建议、要求少说话和转换话题，避免每次回应都追加问题、安慰模板或行动清单。

### 4.2 首版只保存用户主动要求并确认的少量偏好

当前上下文先使用有上限的最近消息窗口。首版不建设自动摘要、自动事件提取和复杂检索，不在每次倾诉后主动要求确认记忆。

用户主动提出保存称呼、回复长短、倾诉时不想立刻听建议等偏好后，展示保存内容和范围，确认后写入。模型推断不升级为事实；敏感经历不作为首版偏好记忆自动保存。

每条记忆记录用户作用域、内容、最少确认来源、确认时间、创建/更新时间、版本和撤回状态。只有写入成功才确认“已记住”，资料文本不能提升为系统指令。查看、更正、撤回和全部删除须有确定操作入口，详见第 6 节。

### 4.3 第二阶段的启动条件

跨会话事件记忆和摘要需先证明需求，并能处理事实更新、过期、来源删除。主动跟进需单独验证用户意愿、真实送达、取消、静默时间和预览隐私，默认关闭，不以依赖或使用时长为目标，不用“不回我我会难过”等话术施压。

第二渠道需要用户需求与账号准入实测。跨渠道共享记忆须在两个渠道分别确认绑定，并有可验证的解绑规则，不能凭昵称或头像合并身份。这些均不构成首版验收依赖。

## 5. MVP 范围与交付条件

| 优先级 | 内容 | 完成或启动条件 |
| --- | --- | --- |
| 首版必须 | 单渠道白名单、稳定人格、有上限的多轮上下文、基本风险响应与输出检查 | 对话及工程验收通过 |
| 首版必须 | 用户主动要求并确认的少量偏好记忆；查看、更正、删除；不保存模式 | 控制结果可查，隔离与数据生命周期测试通过 |
| 首版必须 | 简单反馈、超时退路、投递状态、预算上限、最少运行指标 | 故障及预算触顶行为明确 |
| 第二阶段 | 跨会话事件记忆、自动摘要 | 用户确有需求，更新、过期及删除规则可执行 |
| 第二阶段 | 用户授权的主动跟进 | 独立验证意愿、送达、取消与静默规则 |
| 第二阶段 | 微信或其他第二渠道、跨渠道绑定与解绑 | 用户需要且渠道准入通过 |
| 后续评估 | 语音、数字人、多角色、复杂工具、向量检索、微调 | 有明确需求或实测瓶颈 |

群聊陪伴、全量聊天记录导入、浏览器或终端操作、自动访问通讯录和多 Agent 编排均不在首版范围。增加能力必须更新对应的授权、数据及验收规则。

## 6. 数据规则与用户控制

以下为建议默认值，部署前依据实际供应商能力、预算和用户说明确定。云模型路径未明确前仅用合成数据。普通模式与不保存模式均需说明平台及供应商的数据处理边界。

### 6.1 保存范围

| 数据 | 普通模式 | 不保存模式 |
| --- | --- | --- |
| 本方消息与回复原文 | 明示期限，建议首轮最多 7 天，支持提前删除 | 不进入本方持久队列、数据库、摘要、内容日志或故障转储 |
| 当前上下文 | 有长度上限，到期清理 | 仅进程内存；建议空闲 30 分钟或用户结束时清除，绝对存活上限暂定 2 小时 |
| 偏好记忆 | 确认后独立保存，首轮暂以试用结束清理，可提前撤回 | 不提取、不创建、不更新；默认不读取既有偏好记忆 |
| 去重及控制状态 | 只存必要字段并独立清理 | 可保留短期消息 ID、保存模式、授权及删除版本等必要状态，不含原文 |
| 运行指标 | 不含原始倾诉内容，限制访问及期限 | 相同规则，不以可还原摘要或隐藏字段代替原文 |
| 平台及供应商持有的数据 | 按实际服务条件披露 | 只承诺本方不持久化的范围，不承诺第三方零留存 |

空闲、绝对期限、窗口上限、元数据与备份期限必须配置化并在试用前固定。去重元数据建议保留 24 小时，超过期限的去重能力按实际范围说明；匿名运行指标与本方备份建议最多保留 7 天。授权、模式与删除标记保存到相应恢复风险消失，不含可还原的倾诉内容，具体范围告知用户。

### 6.2 控制操作的确定语义

- 同时支持自然语言与固定命令或按钮，例如“查看记忆”“更正偏好”“忘记这条偏好”“删除本方全部对话及记忆”“停止当前回复”“开启不保存”。固定入口名称在实现时统一并纳入测试。
- 自然语言指令对象不清时先澄清；收到明确的停止、删除或模式切换请求时立即使相关在途任务失效，不能排在长对话队尾。
- “忘记这条偏好”撤回指定条目及本方用于恢复该条目的确认来源和派生状态，不默认删除无关对话；“删除本方全部对话及记忆”覆盖本方历史、回复、偏好及相关任务。分别说明结果及范围。
- 更正生成新版本，旧版本不再检索。删除确认来源时，同步删除依赖它的记忆等派生数据；后台提交前重查版本，禁止把旧事实写回。
- 模式路由发生在原文持久化之前。不保存模式只用内存任务，进程重启后无法恢复未完成会话；关闭该模式后不补存此前内容。
- 切换不保存模式时清理本轮内存上下文并失效在途任务，后续消息走新路径。已有普通模式历史不会因切换自动全部删除，需明确展示清理入口。
- 所有用户控制结果以实际执行状态为准，失败或部分完成时如实报告，不仅凭模型文字确认。

### 6.3 删除与并发、备份的关系

删除操作更新用户数据版本并取消相关任务。后台生成及待发送结果在写入数据库、更新记忆和交给渠道前重查授权、数据版本及取消状态；不匹配时丢弃。

发送交接与删除之间需定义明确的先后边界，通过受控提交状态保证删除后旧任务不会重新开始交接；已交给平台的消息按平台实际撤回能力说明，不保证召回。记录最少操作状态供核验，不写原文。

删除覆盖本方数据库、队列、内存缓存、确认来源和已有派生数据。备份中内容按明示期限失效；恢复前重放最少删除标记及必要的更正/授权版本，再开放服务，不能恢复已撤回偏好或已撤销访问。删除标记至少覆盖所有可能恢复该数据的备份寿命，测试恢复流程。

## 7. 技术流程和运行规则

采用 Python、FastAPI、SQLite 和单主机的模块化单体。官方 SDK 直连是候选，框架仅在第 2 节实验通过后作为适配层；独立核心负责用户、上下文、策略及控制规则。

~~~mermaid
flowchart TD
  A[渠道身份与授权] --> B[去重、保存模式和控制请求路由]
  B --> C{任务类型}
  C -->|停止、删除、模式切换| D[优先更新状态并失效在途任务]
  C -->|普通对话| E{保存模式}
  E -->|普通| F[持久任务与用户顺序队列]
  E -->|不保存| G[仅内存任务]
  F --> H[近期上下文与已授权偏好]
  G --> H
  H --> I[需求及风险判断、回复生成]
  I --> J[完整输出检查]
  J -->|通过| K[重查授权、数据版本和取消状态]
  K --> L[发送及记录最少投递状态]
  J -->|异常| M[审核过的简短故障提示]
  M --> K
~~~

### 7.1 初始实现

| 层 | 选择 | 范围与升级条件 |
| --- | --- | --- |
| 服务 | Python + FastAPI | 清晰流程及 provider 接口，不使用通用无限工具循环 |
| 接入 | 验证后的唯一渠道适配器 | 保留身份、消息 ID 及发送结果，按模式处理原文 |
| 上下文 | 有上限的最近消息窗口 | 首版不自动摘要；长度与 token 预算在模型初筛后固定 |
| 存储 | SQLite 单实例 | 普通模式消息、确认偏好、任务及最少控制状态；多实例或写入压力经测量后再迁移 |
| 任务 | 单个 worker、不同用户有限并发 | 普通模式任务可持久化；不保存任务仅在内存 |
| 模型 | 可替换 provider 层 | 锁定通过评测的模型版本及配置 |
| 部署 | 单台持续运行主机 | 首次试用前补齐凭证管理、访问控制、备份和监控 |

定时跟进调度是第二阶段独立能力，不与首版普通对话 worker 混为一项必做功能。

### 7.2 顺序、授权与故障行为

1. 同一用户普通对话有序执行，适度合并快速连续短消息；不同用户有限并发。控制请求走优先路径，可使正在生成的结果失效。
2. 风险判断读取相关近期上下文，遵循当前保存模式，不只依据本轮关键词。简单对话尽量合并判断与生成，不默认每轮分别调用多个模型做分类、提取、摘要和检查。
3. 首版完整生成、检查后发送。检查异常不放行草稿，返回事先审核的简短故障提示；标明超时、模型错误或检查不可用等内部失败类型，日志不记录内容。
4. 模型或检查暂时故障，最多重试一次且遵守总超时与预算；检查不通过时不发送原草稿。重试仍失败则使用审核提示，不伪造保存或发送结果。
5. 入站按渠道及消息 ID 去重，出站保存业务请求 ID 和投递状态。结果未知时记录未知；只有渠道具备可靠幂等或查询能力时才据此补发，不承诺跨所有故障绝对只回复一次。
6. 所有读写、用户控制及候选记忆必须带用户作用域，授权在模型调用与内容存储前执行；发送前再次检查撤销与取消状态。
7. 凭证、数据库备份和密钥分别管理；关闭代理、SDK、模型调用链及错误转储中的内容日志。对日志进行核验，不能仅依赖业务层“没有打印”。
8. 偏好保存由明确控制操作触发。服务提供确定接口校验内容、确认及版本，不能由模型自行声称已经执行。

## 8. 响应边界

第一版定位日常情绪支持，明确 AI 身份，避免诊断、用药建议和治疗效果承诺。这些响应流程、输出检查与故障退路必须在首次试用前通过验收。

对自我否定，理解痛苦并温和区分挫折与自我价值；对未经证实的被害判断不直接附和；不鼓励排他依赖或操控现实人际关系。

可能存在即时自伤或伤人危险时，结合多轮上下文采用关切、直接且简短的响应，澄清当下是否安全，鼓励联系身边可信任的人与当地紧急支持。资源来自经过核验、可更新的地区资源库，不能让模型编造号码或机构。普通难过、玩笑和引用内容的误报也纳入评测。

如果以后提供真人转接，必须有真实可用服务及授权流程。首版不声称有人实时监控，不自动向联系人转发倾诉内容。检查超时也不放行未经检查的生成内容。

## 9. 模型、策略和工程验收

### 9.1 分开验证策略与记忆

在第 2 节模型初筛后，固定同一模型、参数及提示词版本，比较：

- A：普通聊天人设，无持久记忆。
- B：陪伴策略，无持久记忆。
- C：同一陪伴策略，启用已确认偏好记忆。

用 B 对 A 验证策略，用 C 对 B 验证偏好记忆；主动跟进进入第二阶段后另设实验。对照条件保持相同消息窗口及共同历史，记忆测试在新会话中不把所有待回忆事实重新放入输入。

先用约 20 个多轮开发场景筛查明显问题，再构建独立验收集，暂定约 60–100 个脚本，实际数量在正式验收前固定。首版覆盖工作挫败、倾诉偏好、连续拒绝建议、少说话、话题转换、记忆不足、纠正和撤回、用户隔离、保存模式、即时危险及误报。过期用例覆盖首版消息及上下文期限；未来事件记忆需单独扩展验收。

人工盲评随机交换答案顺序，允许平局，预先定义贴合程度、建议时机、套话、不当附和和长度等规则。分别报告场景数、独立评审数、胜平负及不确定性；同场景重复评分不作为独立用户样本。关键样本尽量两人独立复核并记录分歧处理；无法安排时注明评审局限。模型评委只作辅助筛查。

### 9.2 首版验收表

下列数值为启动参数，需在查看验收结果前固定，不是行业标准或已达到的效果。

| 维度 | 定义与初始判断方式 |
| --- | --- |
| 对话增益 | 胜率 = 胜场 / 非平局场景数，平局率另列；60% 为初始目标，报告区间。全部平局时胜率不可计算；证据不足记为未确定，不仅凭点估计扩大试用 |
| 记忆引用精确率 | 正确且获授权的持久记忆事实引用数 / 全部持久记忆事实引用数，目标 ≥95%；单列编造引用，无引用时不记为 100% |
| 记忆召回率 | 正确回忆的已确认事实数 / 脚本预先标注应回忆的事实数，目标 ≥90%；分母为零则不适用 |
| 撤回与更正 | 删除、撤回、过期或被更正的事实不再作为有效事实引用，固定脚本全部通过 |
| 授权与用户隔离 | 固定测试中跨用户引用、未授权写入、撤销后访问为零；出现即阻止进入或扩大试用 |
| 不保存与删除 | 核查数据库、任务、内存、日志及重启；覆盖在途生成、发送前取消和备份恢复，规定场景全部通过 |
| 消息可靠性 | 重复事件、连发、断网、重启、模型超时、检查异常、未知投递均符合预期，有可查状态 |
| 响应耗时 | 从收到完整用户消息到渠道确认发送的端到端 P50/P95；目标 P95 ≤10 秒，分别报告单用户与 5 用户并发条件、网络、模型及回复长度 |
| 关键响应边界 | 独立固定集人工复核全部通过，包含多轮语境、普通难过误报及检查超时退路 |
| 费用 | 单轮、长对话、失败及重试、每日费用与预算触顶行为可核验 |

等待用户控制确认的时间不混入模型回复延迟；未获渠道确认的请求单列失败或未知，不作为成功样本排除后隐藏。固定测试集通过只说明这些样本上的版本表现，不推出真实世界零风险或百分之百可靠。

### 9.3 受邀试用与决策

首次试用前完成准入、离线体验、工程、数据和费用验收。约 5–10 名成年人自愿试用，实际观察 7–14 天；人数是便于单开发者处理反馈的计划参数，不用于推断市场规模。

自然会话结束时低频询问是否觉得被理解，并提供“不需要建议”“记错了”“太啰嗦”等反馈。报告有效会话定义、会话数量、反馈覆盖率、错误、入口障碍、延迟及成本；访谈退出者，留存仅作辅助，不追求更长聊天时间或临床效果推断。

策略未显示稳定增益时先改策略；偏好记忆无增益时先检查需求和事实质量。出现授权、删除或隔离问题，暂停相关能力或试用，修复并回归后恢复。只有记忆有增益且用户需要时，再扩展事件记忆与跟进。

## 10. 分阶段实施安排

假设一名具备 Python 与模型 API 经验的开发者，单渠道、最小偏好记忆且平台条件及时可用。计划约三周开发验收，随后完整观察 7–14 天；不承诺四周内完成全部工作。工作预算相加超出可用工作日则顺延，平台、招募等待及修复单列，不压缩验收与观察期。

| 阶段 | 建议工作预算 | 交付及退出条件 |
| --- | --- | --- |
| 第 1 周 | 定位访谈约 1–2 天；渠道和集成实验约 1–2 天，其中框架实验限半天至一天；模型初筛与基线约 1–2 天 | 一页决策记录、证据表、代表受邀用户的加入收发实测、实际首发入口、可运行基线、开发集及验收集初稿 |
| 第 2 周 | 单渠道上下文与策略约 2 天；最小偏好记忆和控制约 2 天；风险响应、故障退路及指标约 1–2 天 | 对话可用，查看更正删除及不保存可执行，隔离测试通过 |
| 第 3 周 | 盲评与回归约 1–2 天；并发故障与生命周期测试约 1–2 天；修复和部署核验约 1–2 天 | 发布验收记录、数据处理说明、预算和限流配置，关键失败清零后才进入试用 |
| 第 4–5 周 | 招募约 5–10 名成年人，完成 7–14 天实际观察、低频反馈和退出访谈 | 体验、可靠性、数据控制、入口障碍、延迟与成本报告，形成下一阶段决策 |

阶段结束依据退出条件推进，日期随实际结果更新。渠道失败则调整唯一入口；策略无增益则调整策略。仅自用时裁剪多用户建设，另估配置与测试预算；第二阶段能力另立范围、工期和验收。

## 11. 成本、预算和运行决策

### 11.1 保留流量算式，使用真实单价

每个候选记录 provider、模型版本、计费单位、缓存规则和官方报价日期。流量示例不代表首轮试用规模：20 名日活用户，每人每天 30 次输入/回复，每次平均输入 2,000 token、输出 200 token，按 30 天计算：

- 输入 3,600 万 token / 月。
- 输出 360 万 token / 月。

若输入、输出价格为同一币种每百万 token 的 P_in、P_out，主对话成本约为 36 × P_in + 3.6 × P_out。额外检查、记忆操作、重试及基础设施另计，缓存按实际命中统计。该算式是预算例子，不是厂商报价。

### 11.2 实测预算表

第一周填写低流量、预期流量和长上下文三种情形，数值未测量时标为待测，不直接复用示例作为报价。

| 计量项 | 低流量 | 预期流量 | 长上下文 / 故障情形 | 记录方式 |
| --- | --- | --- | --- | --- |
| 主回复 | 待测 | 待测 | 待测 | 输入/输出 token、缓存、模型版本、实际费用 |
| 记忆控制操作 | 待测 | 待测 | 待测 | 区分本地确定操作与实际付费调用 |
| 额外输出检查 | 待测 | 待测 | 待测 | 调用次数及单独计费量，不默认免费 |
| 失败与重试 | 待测 | 待测 | 待测 | 纳入所有已计费调用及失败类型 |
| 主机、日志及备份 | 待测 | 待测 | 待测 | 按实际账单、资源与期限估算 |

### 11.3 预算和降级行为

第一周确定试用总预算、每日预算、单用户限额及并发上限。新调用前预留预算，并发调用用统一额度控制，结束后按实际计费结算；记录成功、失败、重试及缓存费用。

预算触顶前预留少量固定控制和故障通知资源，查看、删除、停止等本地控制不依赖付费模型继续可用。触顶后停止新付费对话并明确提示，不静默切换到未评测模型。服务恢复或额度重置按预先确定规则执行。

主模型故障时诚实提示稍后重试；备用模型必须独立通过同一验收才可启用，并记录切换。观察“每次有帮助的会话成本”时同时报告反馈覆盖率，不能把少数主动反馈代表全体。
